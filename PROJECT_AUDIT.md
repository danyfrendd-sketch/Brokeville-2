# Аудит проекта Brokeville 2

Дата проверки: 2026-10-28  
Ветка аудита: `audit/project-hygiene-2026-10-28`  
Объём: дерево `main`, основные HTML/JSON/Python/workflow-файлы и известные ссылки. Геометрия GLB не перестраивалась. Никакие существующие файлы не удалялись.

## Краткий вывод

Репозиторий содержит **две параллельные задачи**:
1. 3D-прогулка по реальному Пиетарсаари (`play.html` + GLB + Python-генератор).
2. Карта вымышленного Brokeville по картинке (`index.html` + `map-layout.json` + anchors/references).

Это не обязательно дубликаты: это разные прототипы. Но сейчас их назначение и связь плохо объяснены в корневом README. Сначала стоит решить, должны ли они остаться в одном репозитории; до решения безопаснее сохранить оба.

## Подтверждённые проблемы

### 1. Путь генератора не совпадает с путём игры

- Клиент загружает `./map/preview/pietarsaari_3d.glb`.
- Генератор пишет `map/data/pietarsaari_3d.glb`.
- В репозитории не найден `map/data/pietarsaari_osm.geojson` в текущем дереве.
- Текущий workflow намеренно только проверяет существование GLB и `play.html`; он не скачивает данные и не перестраивает модель.

Следствие: запуск генератора сам по себе не обновит опубликованную модель. Это нужно исправить отдельным изменением с проверенным исходным GeoJSON и безопасным выходным файлом; не направлять генератор сразу на текущий GLB.

### 2. Нет автоматической проверки проекта

До этой ветки в проверенном дереве не было отдельного workflow для проверки JSON и синтаксиса Python. Новый workflow добавляет только базовые проверки файлов; он **не** доказывает, что 3D-карта корректна в браузере.

### 3. Внешняя зависимость в просмотрщике чертежа

`index.html` загружает исходное изображение по URL Catbox. Если хостинг недоступен или файл удалён, просмотрщик показывает сообщение об ошибке. В репозитории есть JPEG в `map/references/`, но без визуального сравнения нельзя безопасно считать его тем же самым изображением и автоматически подменять.

### 4. Смешение двух картографических задач

Названия `map-layout.json`, `anchors-v1.json`, `city_map.json` относятся к схеме Brokeville, а скрипты `build_pietarsaari_3d.py` и `MANUAL_PIETARSAARI_3D_BUILD_TASK.md` — к реальному Пиетарсаари. Это объяснимо для прототипа, но должно быть чётко отражено в документации и структуре.

## Соединения и зависимости

- **GitHub Pages:** `index.html` и `play.html` — статические страницы; записи в папку `logs/` из браузера не происходит.
- **Three.js:** импортируется через `https://esm.sh/three@0.160.0` и GLTFLoader с того же CDN. Это внешняя runtime-зависимость.
- **GLB:** путь v1 локальный относительно `play.html`; v2 разрешён в селекторе, но отдельный `pietarsaari_3d_v2.glb` в проверенном дереве отсутствует. Не считать v2 рабочим до появления файла и браузерного теста.
- **Исходная картинка схемы:** Catbox URL в `index.html` и в `map/README.md`; это повтор одной внешней ссылки, не локальная копия.
- **OSM/elevation:** Python-скрипты обращаются к внешним сервисам при импорте/сборке. Текущий workflow их не запускает.
- **Логи:** клиент сохраняет диагностику в localStorage и позволяет скачать JSON-отчёт; это не GitHub Actions лог и не файл в репозитории.
- **GitHub Actions:** workflow сборки по факту только проверяет два файла; новый workflow проверяет JSON и синтаксис Python.

- ZIP: 2,594,515 байт; SHA-256 `96a640b49f27c8213d1cb0387ec6b1426ff5a50943b18f5ab8b9aeebc91a33e8`.
- Распакованный GeoJSON: 14,994,747 байт; SHA-256 `cb6511ce4c1da0a58394fcb3203765d6af55d2d7762d6d674d7f036fec110cd2`.
- Формат: `FeatureCollection`, 34,934 объектов: 28,882 Polygon и 6,052 LineString.
- Основные свойства включают `building` (27,285 объектов) и `highway` (5,725 объектов). Это совпадает с ожидаемым типом источника для генератора.
- Архив всё ещё доступен в Actions и указан с истечением срока 2026-11-26. Исходник извлечён и проверен локально в текущей рабочей сессии, но **ещё не закоммичен в репозиторий**.

Не запускать новый Overpass download: сначала сохранить проверенный источник в репозитории или в долговременном архиве и проверить лицензионную атрибуцию.

5. После этого — переименовать workflow, объединить повторяющиеся инструкции и решить, держать ли обе карты в одном репозитории.
